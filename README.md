# Pantry

把一台淘汰的安卓手机改成家用照片储存库，附带一些磁力搜索、离线下载等小工具。

做这个的起因是不想买小米云服务的会员。工作照片攒得太多，作为土木狗隔三差五拍一堆工地照片，考虑到工作留痕不愿删。时间长了相册非常臃肿，工作照片和家人的照片混在一起，找起来很费劲。手机云服务免费容量不够用，丢手机也有丢照片的风险。所以有了这套把旧手机改成丐版 NAS 的方案，原则是废物利用，能省则省，能白嫖绝不氪金。

## 和成熟相册软件的区别

手机自带的相册 app 和成熟的照片管理软件，照片是自动分类，但决定是软件做的。它把一张施工中的建筑照片放进「建筑」相册，不会添加更具体的说明，需要人看到后从记忆里找出这张照片的拍摄目的。

Pantry 反过来，突出一个好记性不如烂笔头。新拍的和手机里存量的照片，都要人工判明用处、手动分类、建立事件，用文字记下拍这些照片的目的，靠文件夹名把信息固定下来。

通过调用免费的 VLM 提前读图，给出候选事件和关键词，省掉一部分手工。

- 每张归档照片的目录名都能直接看出用途。
- 模型给的建议错了，不采纳就行，不影响结果。
- 不配在线模型也能用，只是没有辅助候选，得自己建事件。配了的话，照片会以 base64 传给模型厂商，这是全套系统里唯一会出局域网的地方，不想传就别配。

## 目录长什么样

```
/data/media/0/nasbak/
├── inbox/          新收进来、还没归类的
│   └── 2024-05-12/  先按拍摄日期分好
├── archive/        归好类的
│   └── 2024-05/     按月分卷，事件夹在里面
├── _media_gc_trash/ 回收站，留 30 天
└── state/          索引和账本
    ├── ledger.jsonl
    ├── decisions.jsonl
    ├── receipts.jsonl
    └── thumb/
```

归档后长这样，名字带日期和事由，数据线连上电脑就能按名字翻到那一年那件事：

```
archive/2024-05/
└── 2024-05-12 老宅翻修-屋面防水验收/
    ├── IMG_20240512_0931.jpg
    ├── IMG_20240512_0934.jpg
    └── _event.json
```

`state/` 删掉不会丢照片，事件目录里的 `_event.json` 也跟着照片走，拷走不会丢。但账本里记的「什么时候收进来的、谁判的」会一起没，缩略图也得重建，所以别删，真要清先备份。

## 两部分

| 装在哪 | 谁在用 | 现在是什么 |
| --- | --- | --- |
| 服务端 | 当库房的那台旧手机，插电放着 | shell 脚本 + busybox httpd，靠 Magisk 起 |
| 用户端 | 家里其他人的手机 | WebView 壳 APK，已完成 |

两边不能合并。服务端要常驻、要读写存储、要开机自启；用户端只是个浏览器壳，装上填个地址就完事。塞进同一个包里，权限和界面都要迁就两头。

服务端 App 的架子已经搭起来了（`apps/server/`）：申请文件权限、前台服务、解压运行时、起 httpd 的入口都有。但还不能直接当库房用，脚本里约 48 处硬编码路径没收干净，busybox 和 ffmpeg 也还没按 Android 10+ 的规矩装进 nativeLibraryDir。这两件做完才能脱掉 Magisk。

## 现在有什么

自动备份手机照片、按拍摄日期归位、生成缩略图、VLM 给候选事件和关键词、人工确认后归档、按年和事件折叠浏览（事件内可切换按存入时间还是拍摄时间分批）、30 天回收站、同步到云盘、网页里看手机屏幕并反向操作、局域网自动发现库房。

没有多用户、没有分享链接、没有 iOS 版、没有人脸识别。分享这条尤其不会加，它意味着对外开一个口子，照片本来就该留在自己硬盘上。

## 跑起来

要一台 root 过的安卓手机（Magisk），和一台能跑 adb 的电脑。**仓库里只有脚本和页面**，busybox、ffmpeg、alist、aria2 这些二进制要自己放到设备上；拍照手机往库房传照片的同步工具也不在仓库里，用任意文件夹同步工具把 DCIM 送进 `inbox/Camera/` 就行。

```powershell
$env:ADB_DEVICE = "<手机IP>:5555"
.\deploy\deploy.ps1
```

脚本先把文件推到 `/data/local/tmp/stage`，再 `su -c` 复制到 `/data/adb/nasbak/`（`/data/adb` 权限 700，直接 push 会被拒），顺带给 CGI 加执行位、重启 httpd 和 daemon、逐个页面验返回码。

开机自启靠 Magisk 的 `service.d`：`srv.sh` 拉起 aria2 和 alist，`zzz-nasbak.sh` 起 8083 的 httpd 和 30 分钟一轮的 `daemon.sh`。定时任务走 GGAT_10007 模块自带的 crond。

浏览器打开 `http://<手机IP>:8083` 就是面板，第一次进去是三步向导：选库房、连网络（可跳过）、设管理员 PIN。自动判读要配多模态模型的 key，写在 `bin/vlm_classify.sh` 里，不配也能用。

装完按七条验收走一遍：ping 探针、向导、丢张照片看判定页、归档出事件夹、存档页放大和播视频、手机 App 自动查找、重启后服务自己回来。完整步骤、端口表、排障和恢复出厂重建顺序见 [`docs/部署说明.md`](docs/部署说明.md)。

一句提醒：**8083 没有鉴权**，只在自己家 WiFi 或组网里用，不要做端口映射把 8083 放到公网。

两个 APK 在 `apps/client/`（看照片）和 `apps/server/`（当库房）。改完 `git push`，GitHub Actions 会各出一个包，从 artifact 取。本机不用装 JDK、SDK 或 Gradle。
