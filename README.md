# Pantry

把一台淘汰的安卓手机改成家里存照片的地方。

照片按事件存成普通文件夹，名字带日期和事由：

```
archive/2024-05/
└── 2024-05-12 老宅翻修-屋面防水验收/
    ├── IMG_20240512_0931.jpg
    ├── IMG_20240512_0934.jpg
    └── _event.json
```

不装任何软件，数据线连上电脑就能按名字翻到那一年那件事。哪天程序坏了、手机换了、
当初用的什么工具也忘了，这些文件夹还在，还认得出是什么。

一台旧手机待机 1–3W，自带电池相当于免费 UPS，自带屏幕本地排障不用连电脑。
选它不选群晖或树莓派，就是因为这三条。

## 为什么每批照片都要人确认一次

人脸和定位能告诉你这是谁、在哪，但答不了"这张是干什么用的"。工地验收、材料进场、
孩子某次演出——这些东西算法看不出来，只有当时在场的你记得。

所以归档前要人确认一次归属，顺手留一行说明。一次几十张，几十秒。

代价是这套东西不会自己整理好，得有人管。

## 两部分

| | 装在哪 | 谁在用 | 现在是什么 |
|---|---|---|---|
| 服务端 | 当库房的那台手机，插电放着 | 平时不用管 | shell 脚本 + busybox httpd，靠 Magisk 起 |
| 用户端 | 家里其他人的手机 | 看照片、上传、判定 | WebView 壳 APK，已完成 |

这两边得是两个 app，不能合并。服务端要常驻、要读写存储、要开机自启；
用户端只是个浏览器壳，装上填个地址就完事。塞进同一个包里，权限和界面都要迁就两头。

服务端 App 的架子已经搭起来了（`apps/server/`）：申请文件权限、前台服务、
解压运行时、起 httpd 的入口都有。但还不能直接当库房用——脚本里 48 处硬编码路径
没收干净，busybox 和 ffmpeg 也还没按 Android 10+ 的规矩装进 nativeLibraryDir。
这两件做完才能脱掉 Magisk。

## 目录长什么样

```
/data/media/0/nasbak/
├── inbox/                    新收进来、还没归类的
│   └── 2024-05-12/           先按拍摄日期分好
├── archive/                  归好类的
│   └── 2024-05/              按月分卷，事件夹在里面
├── _media_gc_trash/          回收站，留 30 天
└── state/                    索引和账本
    ├── ledger.jsonl          什么时候把什么搬到了哪
    ├── decisions.jsonl       人工判定记录
    ├── receipts.jsonl        每次收取的回执
    └── thumb/                缩略图缓存，删了会自己重建
```

`state/` 整个删掉不会丢照片，只是下次打开要重新扫一遍生成索引。
事件目录里的 `_event.json` 存当初写的那句话，和照片放在一起，拷走也不会丢。

## 跑起来

要一台 root 过的安卓手机（Magisk），和一台能跑 adb 的电脑。

1. 手机开无线调试，`adb connect <手机IP>:5555`
2. `.\deploy\deploy.ps1` 把 `bin/ www/ service.d/` 推上去
3. 重启手机，`zzz-nasbak.sh` 会把 httpd 和定时任务拉起来

浏览器打开 `http://<手机IP>:8083` 就是面板。

自动判读要配多模态模型的 key，写在 `bin/vlm_classify.sh` 里。不配也能用，
只是照片进不了待判定列表，得自己建事件夹往里放。

两个 APK 在 `apps/client/`（看照片）和 `apps/server/`（当库房）。改完 `git push`，
GitHub Actions 会各出一个包，从 artifact 取。本机不用装 JDK、SDK 或 Gradle。

## 现在有什么

自动备份手机照片、按拍摄日期归位、生成缩略图、人工确认后归档、按年和事件折叠浏览
（事件内可以切换按存入时间还是拍摄时间分批）、30 天回收站、同步到云盘、
网页里看手机屏幕并反向操作、局域网里自动发现库房。

没有多用户、没有分享链接、没有 iOS 版、没有人脸识别。

分享这条尤其不会加。它意味着对外开一个口子，而这套东西的价值就在于照片不出你家网络。
