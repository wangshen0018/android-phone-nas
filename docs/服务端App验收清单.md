# 服务端 App 验收清单（pantry-server 0.2.1）

这份清单是给「第一次把服务端 App 装到真机上」用的。0.2 系列到目前为止只在电脑上
用解压出来的脚本跑过，Java 那层（HTTP 服务、缩略图、定时轮询）**一次真机都没跑**，
所以下面每一项都要真的点一遍，不能看着像对的就跳过。

装包与首次配置见 `交付/pantry-apk/安装说明.txt`，这里只讲怎么验证它对不对。

---

## 零、测试前要知道的

| 项 | 值 |
|---|---|
| 包名 | com.pantry.server |
| 端口 | 8083，无鉴权，只在自己家 WiFi 里用 |
| 照片存哪 | 共享存储 `Pantry/`（`inbox/`、`archive/`、`state/`） |
| 日志在哪 | App 私有目录 `files/runtime/logs/app.log`，超 512KB 轮转成 `app.log.1` |
| 运行时脚本 | App 私有目录 `files/runtime/`，首次启动解压，升级 APK 自动换新 |
| 自动归位 | 启动后约 20 秒跑第一轮，之后每 30 分钟一轮 |
| 一轮做什么 | `move-by-date.sh --apply` → `judge.sh --ingest` → 有归位就 `judge.sh --judge` |

两点先说清楚，免得误判成 bug：

1. **重启手机后服务不会自己起来**（0.2 没做开机自启）。断电重来之后要手动打开 App
   点一次「启动 / 重启服务」。
2. **磁力搜索、迅雷、投屏、云盘同步点了会 404**，这些功能要 aria2/alist/scrcpy，
   APK 里不带。这不是缺陷，是取舍。

## 一、装与启动

- [ ] 安装包能装上，图标是深靛蓝底储物柜
- [ ] 首次打开提示「1 开启文件访问权限」，跳转到系统设置后能开启「所有文件访问」
- [ ] 回到 App，按钮变成「文件权限：已开启」（灰色，点不动）
- [ ] 点「启动 / 重启服务」，状态从「准备运行时」→「启动面板」→「运行中」
- [ ] 状态区显示「局域网地址：<IP>:8083」，不是「没连上 WiFi」
- [ ] 状态区显示「存储位置：/storage/emulated/0/Pantry」
- [ ] 通知栏出现常驻通知「Pantry 库房 · 运行中」
- [ ] 首次启动解压运行时耗时几秒，不卡死、不闪退

失败怎么看：状态显示「缺文件权限」就是第一步没生效；显示「运行时没准备好」是
APK 里没打进 runtime.zip（构建问题，不是手机问题）；显示「端口被占用」见第六节。

- [ ] 「停止服务」→ 状态变「已停止」，通知消失；再点「启动」能回来

---

## 二、面板与接口（就在这台手机上用浏览器看）

地址都用状态区显示的那个 IP。

- [ ] `http://<IP>:8083/index.html` 能打开首页，样式正常
- [ ] `http://<IP>:8083/cgi/ping.cgi` 返回一行 JSON，含 `"nasbak":1`
- [ ] `http://<IP>:8083/cgi/state.cgi` 返回合法 JSON（面板上的统计数字来自这里）
- [ ] `http://<IP>:8083/cgi/archive.cgi?action=list` 返回 JSON，空库时是空列表而不是报错
- [ ] 从另一台设备（电脑浏览器）用同一个地址也能打开，说明不是只听 127.0.0.1
- [ ] 页面连续刷新几次不出现空白页或半截页面（keep-alive 是否稳）

失败怎么看：502/无响应看通知是否还在、手机是否被系统停掉；返回的是脚本源码
说明 CGI 没被执行；返回 404 说明运行时解压不全。

## 三、收照片

最真实的路径是用用户端 App 传，也可以用电脑直接打接口把服务端单独隔出来测。

- [ ] 用户端 App 自动查找能搜到这台库房（这一步同时验证 ping.cgi）
- [ ] 传一张照片后，`Pantry/inbox/Pantry/<相册名>/` 里出现该文件
- [ ] 中文相册名在文件管理器里能正常显示，`.album.txt` 记着原始相册名
- [ ] 同一张照片再同步一次，App 显示「没有新照片」，服务端不新增文件
- [ ] 不同相册里的同名文件（如两个文件夹都有 `IMG_001.jpg`）都能收到，不互相顶掉

用电脑单独测（把 IP 和文件名换掉）：

```powershell
$ip = "<库房IP>"        # 例：状态区显示的那个地址
$name = [Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes("IMG_test_001.jpg"))
$bk   = [Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes("相机"))
$h = @{
  "X-Pantry-Name"   = $name
  "X-Pantry-Bucket" = $bk
  "X-Pantry-Id"     = "pc-test-1"
  "X-Pantry-Dev"    = "PC"
  "X-Pantry-Taken"  = "1762761600"
}
Invoke-WebRequest -Uri "http://$ip`:8083/cgi/upload.cgi" -Method Post -Headers $h `
  -InFile "C:\path\IMG_test_001.jpg" -ContentType "application/octet-stream"
```

同一个 `X-Pantry-Id` 重复发两次，第二次应当返回 dup 一类的结果而不是再落一份。

- [ ] 大文件：传一个 100MB 以上的视频，能完整落盘，App 不闪退、不 OOM
- [ ] 传坏扩展名（如 `.exe`）被拒，`state/upload.log` 里有记录

大文件这一条最要紧——客户端上传走的是流式转发，真机上内存压力和电脑不一样，
手机传 200MB 视频时留意通知栏和 App 是否还在。

## 四、归位与判定

- [ ] 启动后约 20 秒，「上次归位」出现时间，并带「上轮归位 N 个」或「上轮无新文件」
- [ ] 传进去的照片被搬进 `Pantry/inbox/<拍摄日期>/`，原目录不再有它
- [ ] `.album.txt`、`*.part` 半成品没有被当成照片搬走
- [ ] 判定页 `/judge.html` 能打开，能看到待判定的条目
- [ ] `Pantry/state/media/` 里生成硬链接，`pending.queue` / `analysis.jsonl` 有内容
- [ ] 判定页一次提交 20 条能成功（并发 CGI，单线程 httpd 时代这里是瓶颈）
- [ ] 没配在线模型 key 时，判定页仍有数据（`www/data.json` 能生成），只是没有候选项
- [ ] 手工建事件、把照片归进事件、确认归档，整条能走通

失败怎么看：`app.log` 里搜 `tick`，能看到每轮结果和失败原因。

## 五、归档、浏览、缩略图

- [ ] `archive.html` 能按年折叠，年份、事件、张数都对
- [ ] 事件内能切换「按存入时间 / 按拍摄时间」分组
- [ ] 图片缩略图能出（Java 自己缩的，不走 ffmpeg）
- [ ] **视频缩略图能出首帧**（MediaMetadataRetriever，这一项最容易在国产 ROM 上出问题）
- [ ] 点开能全屏看图、能播视频
- [ ] 手工把一个视频从错误事件移到正确事件，存档页能显示回执
- [ ] 缩略图第二次加载明显更快（说明缓存落到了 `state/thumb/`）

## 六、稳定性与边界

- [ ] 锁屏放 30 分钟以上，回到 App 状态仍是「运行中」，面板还能打开
- [ ] 拔掉充电线、切到别的 App 待一会儿，服务没被杀（需已加电池优化白名单）
- [ ] 与 Magisk 版共存：先停掉那边的 httpd 再启动本 App，不报「端口被占用」；
      反之如果先起 App 再起 httpd，应当是实现后者失败——两边不要同时开着
- [ ] 关闭再打开 WiFi，服务恢复后面板仍可访问、地址显示正确
- [ ] 连续灌 50 张照片，面板不卡死、`app.log` 没有反复重试的记录

## 七、测完回传什么

有问题时按这个格式记，比描述「不太好使」有用得多：

```
手机型号 / Android 版本：
做的是哪一条（第几节第几项）：
期望：
实际：
当时 App 状态区显示：
```

日志取法（调试包支持 run-as，手机不用 root）：

```
adb shell run-as com.pantry.server cat files/runtime/logs/app.log > app.log
adb shell run-as com.pantry.server cat files/runtime/logs/app.log.1 > app.log.1
```

另外顺手截两张图：App 状态区一张，出问题的页面一张。

## 八、这一版已知的坑（测的时候就当已知项，不用报）

1. 重启手机不会自启服务，手动点一次启动。
2. 磁力 / 迅雷 / 投屏 / 云盘同步不可用。
3. 8083 无鉴权，别做端口映射。
4. 判读没有在线模型 key 时只出「未分类」的待判条目，不出候选事件。
5. 首次安装如果手机上还留着 Magisk 版的 `/data/media/0/nasbak`，那是另一套目录，
   与本 App 的 `Pantry/` 互不影响；要迁移历史照片得手工搬。

另外：如果你手上是 **0.2 而不是 0.2.1**，第四节的「20 秒后出现上次归位」必然失败，
那是 0.2 的缺陷（首轮归位被周期判断吞掉，要等满 30 分钟），换 0.2.1 即可，
不用排查手机。
