## 一、改动清单（按重要性排序）

### 1. K80 `nas-backup.sh` —— 重写传输逻辑【最关键】

| | 旧 | 新 |
|---|---|---|
| 目标路径 | `nasbak/inbox/$(date +%F)/Camera` | `nasbak/inbox/Camera`（**固定**） |
| 过滤方式 | 无（rclone 比对目标是否存在） | `--max-age "${AGE}s"`，AGE=当前时间-last_ok_ts |
| 一次运行 | 新增 **1449**，139 秒 | 新增 **0**，1 秒 |

**根因**：旧代码用 `$(date +%F)` 做目标目录，每天都是全新的空目录，
`rclone copy` 认为「目标没有这个文件」→ 每天把 1449 个文件（含 2015 年以来的全部老照片）重传一遍。
2026-11-01 22:22 实测日志：`新增 1449`，其中 1414 个是重复。

**新逻辑要点**：
- 目标目录固定 5 个：`Camera` / `CamScanner` / `scanner` / `family-kid` / `id-card`
- K80 照片的 mtime 就是拍摄时间（已实测验证），所以按 mtime 过滤语义精确
- **不依赖远端文件是否存在**，所以 K40 把 inbox 文件移走后不会误判缺失而重传
- `last_ok_ts`（`/data/local/tmp/nasbak/last_ok_ts`）存上次成功备份的 unix 秒
- 边界保护：无记录→回退7天；间隔<5分钟→拉到5分钟；间隔>400天→压到400天；本轮有错→**不推进**

备份文件：`/data/local/tmp/nasbak/nas-backup.sh.bak-inboxdate-202611020015*`

### 2. K40 新增 `bin/move-by-date.sh` —— 按拍摄日期归位【新功能】

**职责**：把 `inbox/{Camera,CamScanner,scanner,family-kid,id-card}/` 里的新文件，
按**拍摄日期**移入 `inbox/<拍摄日期>/`。这是「K80 不建日期目录、K40 负责归类」的分工落点。

```sh
sh /data/adb/nasbak/bin/move-by-date.sh           # 干跑，只打印计划
sh /data/adb/nasbak/bin/move-by-date.sh --apply   # 真正移动 + 记台账
```

- 日期提取优先级：`IMG_20261020_150836.jpg` 格式 → `2023-12-28` 连字符格式 → `2023_12_28_...` 下划线格式 → 13位毫秒时间戳 → 文件 mtime
- 目标已存在同名文件时：先比大小，再比 **md5**，确认逐字节相同才判定为重复 → 移入 `_dup_backup`
- 同名但内容不同 → 加 `_1` `_2` 序号，绝不覆盖

### 3. K40 新增 `bin/lib-ledger.sh` —— 统一台账库【新功能】

台账文件：`/data/media/0/nasbak/state/ledger.jsonl`（已可从云盘 `照片备份/state/` 取回）

记录字段：`ts / t / id / name / size / act / from / to / note`

动作类型：

| act | 含义 | 由谁写入 |
|---|---|---|
| `recv` | K80 上传到 K40 `inbox/<来源>` | move-by-date.sh |
| `mvdate` | `inbox/<来源>` → `inbox/<拍摄日期>` | move-by-date.sh |
| `arc` | 判定归档 → `archive/<YYYY-MM>/<事件夹>` | apply.cgi |
| `dup` | 判定重复 → `inbox/_dup_backup` | move-by-date.sh / 清理脚本 |
| `del`/`keep`/`hold` | 判定删除/保留/暂不备份 | （沿用 receipts.jsonl，未迁入台账） |

**追溯示例**：查某文件去哪了
```sh
grep "IMG_20261020_150836" /data/media/0/nasbak/state/ledger.jsonl
# → recv: K80/Camera -> inbox/Camera/...
# → mvdate: inbox/Camera/... -> 2026-10-20/...
# → arc: inbox/2026-10-20/... -> archive/2026-10/2026-10-20_work_site-inspection/...
```

台账超过 5MB 时自动轮转，30 天前记录 → `state/ledger-arch/ledger-YYYYMM.jsonl.gz`

### 4. K40 `www/cgi/apply.cgi` —— 注入台账记录

- 头部引入 `lib-ledger.sh`
- 归档成功后（`RES="archived"`）追加 `ledger_add ... "arc" ...` 一条
- 备份：`apply.cgi.bak-ledger-202611020016*`
- 已用 `sh -n` 验证语法

### 5. K40 `gyp-backup.sh` —— 云盘同步语义改造

| | 旧 | 新 |
|---|---|---|
| 同步方式 | `rclone copy`（只增不删） | `rclone sync`（镜像，本地删云端也删） |
| 同步范围 | `archive/` + `inbox/` | `archive/` + `inbox/` + **`state/`（台账与日志）** |
| 排除项 | — | **`_dup_backup/**` 不上云** |

**语义变更原因**（用户 2026-11-01 明确要求）：
> 云盘只是防闪存损坏的保险，不需要永不删除，只需要备份已经存档的成果和待判定的文件，
> 而且待判定的文件一旦归档并移动，云盘也应该相应改动。

所以改成 `sync`：本地 inbox 文件被判定归档搬走后，云端对应副本同步删除。

**state 同步细节**：只挑关键文件（`ledger.jsonl`、`ledger-arch/*.gz`、`move-by-date.log`、`judge.log`、
`cleanup.log`、`events.jsonl`、`receipts.jsonl`、`decisions.jsonl`、`analysis.jsonl`），
不传 `loc-*.tsv` 这类海量碎片（每个文件一个，会撑爆对象数）。

备份：`/data/local/tmp/gyp/gyp-backup.sh.bak-copy-`、`.bak-archive-20261101221934`

## 四、不变量（改任何脚本都必须保持）

1. **K80 的备份目标目录必须固定**（`inbox/Camera` 等）。任何带 `$(date +%F)` 的目标路径都是回归 bug。
2. **K80 绝不删除 NAS 上的任何文件**（用 `rclone copy`，不是 `sync`）。

5. **K80 不做日期归类**，那是 K40 `move-by-date.sh` 的职责。

8. **台账/日志必须同步到云盘 state/**，否则 K40 坏了就丢失追溯依据。

## 六、操作注意事项（踩过的坑）

1. **中文脚本必须 UTF-8 without BOM 推送**，否则中文注释和路径乱码
2. **不要直接 `adb -s X shell "复杂命令含$()或|"`** —— PowerShell 会先解析。
   一律写成本地 `.sh` 文件 → push → `sh 文件` 执行
3. K40 上 `push` 到 root 属主目录（如 `/data/adb/nasbak`、`/data/local/tmp/gyp`）会 Permission denied，
   先 push 到 `/data/local/tmp/`，再 `su -c 'cp ... && chmod 755 ...'`
4. K80 当前 **root 不可用**（`su` 找不到），直接 adb push 即可
5. `/system/bin/sh` **不支持进程替换 `<(...)`**，也**不支持 `find -exec {} +`**（busybox 限制），
   要写成临时文件再用 `comm -12 a b`
6. **不要用 `set -x` 调试**（会刷出几百行 /proc 噪声，且可能把任务拖死）
