# 部署说明

这份讲怎么把它真跑起来。README 只说这是什么，这里全是步骤。

## 先看清仓库里有什么、没有什么

公开仓库只放**脚本、页面、配置**，下面这些要自己准备，仓库里没有：

| 东西 | 从哪来 |
| --- | --- |
| `busybox` | Magisk 自带，路径 `/data/adb/magisk/busybox` |
| `ffmpeg` | 自己放一个安卓静态版到 `bin/`，用于视频抽封面 |
| `alist` | 官网下 arm64 版，放 `srv/bin/alist` |
| `aria2c` | 自己下安卓静态版，放 `srv/bin/aria2c` |
| `rclone` + `rclone.conf` | 云盘同步用，脚本因含个人账号信息未放进公开仓库 |
| 两个 VLM key | 自己去对应平台申请，写成设备上的纯文本文件 |

另外还有个缺口，别照着 README 找：

- **云盘同步脚本没进公开仓库**。要异地备份就自己写一条 `rclone sync`，把 `archive/` 和 `inbox/` 单向镜像出去；建议加 `--backup-dir`，本地误删时云端还能捞回来。

拍照手机往库房传照片这一步已经不用另配工具了。用户端 App（`apps/client/`）自带增量备份：读本机相册，只传勾选的文件夹，把没传过的照片 POST 到 `www/cgi/upload.cgi`，按相册落进 `inbox/Pantry/<相册>/`。`move-by-date.sh` 会连这一层子目录一起扫，后面的归位、判读、归档自动接上。

去重看 `state/upload.idx` 里的稳定键，不是看文件还在不在 `inbox/Pantry/` —— 归位脚本会把文件搬走，只看文件会让清过 App 数据的手机把整批照片重传一遍。用户端和服务端要一起更新到 1.8；旧客户端还能用，但会收进 `未分类/` 且退回按文件名判重。

## 不想刷 Magisk：用服务端 App

`apps/server/` 出的 APK 可以自己当库房，不用 root、不用 Magisk，
也不用把 busybox 塞进 jniLibs。装上之后：给它「所有文件访问」权限 → 点启动 →
面板就跑在 8083。照片存在共享存储 `Pantry/` 下，卸载 App 不会丢。

它和 Magisk 版的差别，先说清楚免得踩空：

| 功能 | Magisk 版 | 服务端 App |
|---|---|---|
| 面板、上传、按日期归位、判定、归档、缩略图 | 有 | 有 |
| 磁力搜索 / 迅雷 / 投屏 / 云盘同步 | 有 | 没有，依赖 aria2、alist、scrcpy 等外部二进制 |
| 开机自启 | service.d | 前台服务，国产 ROM 可能要手动允许自启 |
| 定时归位 | crond + daemon.sh | App 内 Handler，30 分钟一轮 |
| 缩略图 | ffmpeg | BitmapFactory / MediaMetadataRetriever |

两点注意：

1. 8083 只能有一个占用者。之前用 Magisk 部署过的手机，先停掉那边的 httpd 再起 App，
   否则 App 会报「端口被占用」。
2. 两端脚本要同版本。App 里的脚本随 APK 打包，升级 APK 会自动换新
   （用 versionCode + zip 字节数做版本戳，戳变了就重解压，只清 `www/bin/etc`，日志和账本保留）。

App 版路径：脚本在 `/data/data/com.pantry.server/files/runtime`，
数据在 `/storage/emulated/0/Pantry`，日志在 `runtime/logs/app.log`，
临时文件和锁在 `files/tmp`。

## 设备要求

一台 root 过的安卓手机（Magisk），长期插电连着家里 WiFi。Android 11 以上、剩余空间越大越好。库房照片全放在共享存储里，卸载或刷机不会自动清掉，但也别指望系统替你备份。

电脑只要能跑 `adb`。Windows 上直接跑 `deploy/deploy.ps1`，Linux/Mac 照下面的手工路线。

## 目录对应关系

| 仓库路径 | 设备上的路径 |
| --- | --- |
| `bin/` | `/data/adb/nasbak/bin/` |
| `www/` | `/data/adb/nasbak/www/` |
| `httpd.conf` | `/data/adb/nasbak/httpd.conf` |
| `service.d/` | `/data/adb/service.d/` |
| `cron/` | `/data/adb/modules/GGAT_10007/crond/` |
| `srv/` | `/data/adb/srv/` |
| `etc/nasbak.conf` | `/data/adb/nasbak/etc/nasbak.conf` |

数据区单独在 `/data/media/0/nasbak/`，结构是 `inbox/`、`archive/`、`_media_gc_trash/`、`state/`。**代码在 `/data/adb/`，照片在 `/data/media/0/`，两边别混**。

## 部署

`/data/adb` 是 root 所有、权限 700，`adb push` 直接推会 Permission denied。所以脚本走的是「先推到 `/data/local/tmp/stage`，再 `su -c` 复制到位」。

```powershell
# Windows，手机已开无线 adb
$env:ADB_DEVICE = "<手机IP>:5555"
.\deploy\deploy.ps1

# 只改了页面时用这个，省时间
.\deploy\deploy.ps1 -Only www

# 只推文件、不重启服务
.\deploy\deploy.ps1 -NoRestart
```

脚本会顺带做三件事：给 CGI 加可执行位、重启 8083 的 httpd 和 daemon、逐个页面 curl 一遍看返回码。

手工路线（没有 PowerShell 时）：

```sh
adb connect <手机IP>:5555
adb shell "su -c 'echo ROOT_OK'"          # 先确认 root 能用
adb push bin /data/local/tmp/stage/
adb push www /data/local/tmp/stage/
adb shell "su -c 'cp -r /data/local/tmp/stage/bin/* /data/adb/nasbak/bin/; \
  cp -r /data/local/tmp/stage/www/* /data/adb/nasbak/www/; \
  chmod 755 /data/adb/nasbak/www/cgi/* /data/adb/nasbak/bin/*.sh'"
```

## 起服务

开机自启靠 Magisk 的 `service.d`，两份脚本：

- `srv.sh` 恢复无线 adb、唤醒锁、拉起 aria2 和 alist
- `zzz-nasbak.sh` 等开机完成后起 httpd（8083）和 `daemon.sh`

httpd 的启动参数是固定的：

```sh
/data/adb/magisk/busybox httpd -p 8083 -h /data/adb/nasbak/www \
  -c /data/adb/nasbak/httpd.conf
```

改了 html 之后要**杀掉旧 httpd 再起**，不然浏览器拿到的还是旧页。busybox httpd 不发 `Cache-Control`，排障时给 URL 带个 `?v=<时间戳>` 最省事。

定时任务走的是 Magisk 模块 GGAT_10007 自带的 crond，直接敲 `crond` 会 not found。装完 `cron/root` 后要先杀旧进程再用模块的 busybox 起：

```sh
/data/adb/modules/GGAT_10007/busybox/crond -c /data/adb/modules/GGAT_10007/crond
```

`daemon.sh` 自己跑 30 分钟一轮：按拍摄日期归位 → 有新文件才接着判读。夜间集中全量判读已经取消。

## 首次打开

浏览器开 `http://<手机IP>:8083`，第一次会进 `/wizard.html`，三步：

1. **选库房**——自动列出可写的卷和剩余空间，选内部存储或外置卡
2. **连起来**——显示局域网地址；组网那步可以跳过，纯局域网完全能用
3. **定管理员**——设个 PIN，或者选「暂时不设」

配置落在 `state/config.json`。**已经有 `archive/` 或 `inbox/` 但没配置的旧设备会自动补一份，不会被向导拦住**。设了 PIN 之后每次打开默认是浏览模式，看不到「文件判定」和「设置」，切回管理员要点菜单行最左边那个角色项。

删掉 `config.json` 就回到向导。注意 PIN 目前只挡界面，接口层还没校验，知道 URL 的人仍能直接提交判定——别把它当权限系统用。

## 可选功能

**VLM 候选**。不配也能用，只是没有辅助建议，事件全靠自己建。配了的话把 key 写成设备上的纯文本文件，路径在 `bin/vlm_classify.sh` 顶部。要说清楚：**判读时照片会以 base64 发给模型厂商**，这是整套系统里唯一会出局域网的地方，不想传就别配。

**文件管理**。alist 装好后监听 5244，面板里「文件管理」直接 iframe 嵌进去，WebDAV 在同端口 `/dav`。

**下载**。aria2 RPC 在 6800，配置在 `srv/aria2.conf`，`rpc-secret` 自己改一个。磁力搜索依赖境外站点，连不上是正常的，不影响相册功能。

**投屏**。`www/screen.html` 上点「启动投屏」才起，不随开机自启，没人看的时候不占编码资源。

**本机照片备份**。用户端 App 第一次连上库房时会问一次「要不要把这台手机的照片也存进去」，默认关。开了之后先勾选要备份的**文件夹**——相机、截图、微信这些在系统里是分开的相册，各显示张数和占用大小，第一次只预勾相机类，截图不会默认被搬走。也能按返回键点「选择备份文件夹」随时改，或「立即同步一次」手动跑。

同步按 `_id + 修改时间` 判重，中断后重开接着传，不会重头再来；取消勾选某个文件夹，之前传上去的不删，之后新增的也不再传。装到只是看照片的家人手机上，别开这个开关。

**外网**。想在外面看就装 Tailscale 之类的组网工具，走虚拟 IP 访问 8083。**不要做端口映射，不要把 8083 暴露到公网**——这个端口目前没有鉴权，谁连上你家 WiFi 就能读全部照片。

## 验收

按顺序走一遍，全过才算装好：

1. `curl http://<手机IP>:8083/cgi/ping.cgi` 返回带 `"nasbak":1` 的 JSON
2. 浏览器打开面板，向导能走完，左侧菜单齐全
3. 丢一张照片进 `inbox/Camera/`，等一轮 daemon，判定页出现缩略图
4. 判定页选几张、写事件名、确认归档，`archive/<年-月>/<事件夹>/` 里能看到文件
5. 存档页按年折叠、点开事件、缩略图能放大、视频能播
6. 手机装用户端 APK，点「自动查找」能扫出库房，点进去直接是面板
7. 在用户端点「立即同步一次」，库房的 `inbox/Pantry/<相册>/` 出现照片（目录里的 `.album.txt` 写着原始文件夹名），`state/upload.idx` 多出对应记录；再点一次同步应显示「没有新照片要传」。下一轮 daemon 把它归进 `inbox/<拍摄日期>/`
8. 重启手机，httpd 和 daemon 自己回来

## 排障

**页面打不开**：先 `adb shell "ps -A -o pid,args | grep httpd"`，没有 8083 那个就手工起一次。设备休眠后 adb 有时会断，重连一次再看。

**改动不生效**：十有八九是缓存，带 `?v=<时间戳>` 刷新；还不行就杀 httpd 重启。

**CGI 返回 500 或空**：查 `www/cgi/` 下文件是不是 755，`#!/system/bin/sh` 有没有被 Windows 编辑器改成 CRLF。

**缩略图不出**：跑一次 `sh bin/make-thumb.sh`，它会把缺的补齐；视频封面要 ffmpeg 在位。

**存入批次显示「无存档回执」**：手工移动过的文件没有回执记录，索引是合并 `receipts.jsonl` 和 `ledger.jsonl` 两处得出来的，手工搬的时候补一条台账即可。

**照片删了想找回来**：`_media_gc_trash/` 留 30 天，之后 `trash-gc.sh --apply` 才真删。

**手机传上去的照片没进待判**：确认 `www/cgi/upload.cgi` 是 755、`inbox/Pantry/` 可写，再看 `state/upload.log` 有没有收件记录。收了但没归位，检查 `move-by-date.sh` 是不是新版（旧版只扫一层，看不到相册子目录），再就是 daemon 那一轮还没跑。

**同步一次后又整批重传**：多半 `state/upload.idx` 被删了或服务端还是旧版 `upload.cgi`。idx 是去重依据，别和 `state/` 里其它日志一起清；真要清，先备份。

**传上去的照片拍摄日期不对**：1.8 起用 `X-Pantry-Taken` 传 EXIF 拍摄时间，没有 EXIF 的视频退回文件修改时间。旧服务端只认 `X-Pantry-Shot`（修改时间），两端版本不一致时会出现这个现象。

## 恢复出厂后的重建顺序

1. 刷 Magisk，开无线 adb（`persist.adb.tcp.port 5555`）
2. 放 `service.d/srv.sh`，起 aria2 / alist
3. 放两个 `.key` 文件
4. 放 `service.d/zzz-nasbak.sh`，起 httpd 和 daemon
5. 导入 `cron/root`，用 GGAT_10007 的 busybox 起 crond
6. 云盘同步脚本和 `rclone.conf` 就位

**数据区和代码区分开备份**：`archive/` 是成品，拷到任何地方都能直接用文件夹名看懂；`state/` 是账本，一起拷走才保得住「什么时候收进来的、谁判的」。
